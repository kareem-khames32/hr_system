# الدخول المؤسسي (SSO) — دليل الإعداد

الدخول بحساب المؤسسة بـOIDC (Microsoft Entra ID أو Google Workspace). المزوّد بيثبت الهوية بس: الأدوار والصلاحيات ونطاق الفروع من النظام نفسه، والتحقق بخطوتين بتاع النظام بيفضل شغال.

## قبل ما تبدأ

- عنوان الواجهة النهائي (`FRONTEND_URL`) بـhttps.
- كل موظف له في ملفه **بريد العمل** بنفس اسم الدخول عند المزوّد (أو كود الموظف / رقم البصمة في خانة `employeeid` لو المزوّد بيبعتها) — المطابقة بنفس ترتيب «حساب الشركة».
- مستأجر واحد (Single tenant): النظام بيرفض أي هوية من مزوّد أو مستأجر تاني.

## 1) تسجيل التطبيق عند المزوّد

**Microsoft Entra ID:**

1. App registrations ← New registration ← Accounts in this organizational directory only (Single tenant).
2. Redirect URI من نوع **Web**: `<FRONTEND_URL>/login`
3. Certificates & secrets ← New client secret (سجّل تاريخ انتهائه — بيتجدد يدوي).
4. المزوّد (Issuer): `https://login.microsoftonline.com/<tenant-id>/v2.0`

**Google Workspace:**

1. Google Cloud ← APIs & Services ← Credentials ← OAuth client ID ← Web application.
2. Authorized redirect URI: `<FRONTEND_URL>/login`
3. المزوّد (Issuer): `https://accounts.google.com`، وخانة الدخول `email`.

## 2) إعداد الخادم (`api/.env`)

| المفتاح | القيمة |
|---|---|
| `SSO_OIDC_ISSUER` | عنوان المزوّد بالحرف (من الخطوة 1) |
| `SSO_OIDC_CLIENT_ID` | معرّف التطبيق |
| `SSO_OIDC_CLIENT_SECRET` | سر التطبيق — **في `.env` بس**، مايتكتبش في أي مكان تاني ولا يتبعت في رسالة |
| `SSO_OIDC_ALLOWED_DOMAINS` | نطاقات بريد المؤسسة المسموحة، بفاصلة (إجباري) — مثال: `company.com` |
| `SSO_OIDC_LOGIN_CLAIM` | اختياري. `preferred_username` (الافتراضي، لـEntra) أو `upn` أو `email` (لـGoogle — بيشترط إن المزوّد مأكد البريد) |
| `SSO_OIDC_LABEL` | اختياري. اسم الزرار في شاشة الدخول |

من غير الأربعة الأولى الزرار مابيظهرش والمسار مقفول. بعد التعديل: إعادة تشغيل الخادم.

## 3) التجربة

1. شاشة الدخول ← الزرار الجديد ← صفحة المزوّد ← الرجوع للنظام داخل.
2. أول دخول لموظف بيربط حسابه بهويته عند المزوّد (مرة واحدة). الدخول بعد كده بالهوية نفسها حتى لو بريده اتغيّر.

## لو الدخول اترفض

| الرسالة | السبب |
|---|---|
| «حساب الشركة مش مربوط بأي موظف» | مفيش موظف بريد عمله (أو كوده) بيطابق — صحّح بريد العمل في ملف الموظف |
| «حساب المؤسسة ده مش مسموح له بالدخول هنا» | نطاق بريده مش في `SSO_OIDC_ALLOWED_DOMAINS`، أو خانة الدخول مش موجودة في الهوية |
| «حساب الموظف في النظام مربوط بحساب مجال تاني» | الحساب مربوط بهوية تانية (دخول سابق بحساب الشركة أو بهوية تانية عند المزوّد) — الربط مابيتغيّرش لوحده؛ الدعم الفني بيفك الربط القديم الأول |
| «تعذّر إكمال الدخول من مزوّد الهوية» | رد المزوّد اترفض (السبب في سجل الخادم بكود: المزوّد، التطبيق، التوقيع، الصلاحية…) — غالبًا `SSO_OIDC_ISSUER` أو السر غلط أو منتهي |
| «محاولة الدخول المؤسسي انتهت» | المحاولة أقدم من 10 دقايق أو اتفتحت في متصفح تاني — ابدأ من شاشة الدخول |

سجل الدخول بيسجّل كل محاولة بطريقة `SSO`.

## مش مدعوم دلوقتي

- SAML.
- أكتر من مزوّد في نفس النسخة.
- منح أدوار من مجموعات المزوّد (بقرار: الصلاحيات من النظام بس).
- تعطيل الحساب تلقائيًا لما يتقفل عند المزوّد (الدخول نفسه هيترفض عند المزوّد؛ جلسة مفتوحة بتفضل لآخر مدتها).
