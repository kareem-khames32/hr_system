## الرجوع لنسخة قبلها

### الحالة 1: التحديث ماكانش فيه ترحيلات (الأغلب)

الكود بس اللي اتغيّر، والقاعدة زي ما هي:

```bash
git log --oneline -5
git checkout <رقم النسخة القديمة اللي كتبته>
```

بعدين ابني وشغّل زي خطوات 2 و4 و5 في السكربت (أو شغّل السكربت بعد ما ترجّع الفرع لنفس النسخة).

> `update-from-git.ps1` بيعمل `git pull` للفرع، فلو شغّلته بعد `checkout` لنسخة قديمة هيرجع لآخر نسخة. للرجوع المؤقت ابني وشغّل يدوي:
>
> ```bash
> npm ci
> cd api
> npm ci
> npm run build
> cd ..
> npm run build
> ```
>
> وبعدها شغّل الخدمتين زي الخطوة 5 في السكربت.

### الحالة 2: التحديث كان فيه ترحيل اتطبق

الترحيلات إضافية بس (أعمدة وجداول جديدة)، فالكود القديم غالبًا بيشتغل عليها عادي. **جرّب الحالة 1 الأول.**

لو الكود القديم مااشتغلش على القاعدة الجديدة:
1. وقّف الخدمتين.
2. رجّع القاعدة من النسخة اللي خدتها قبل التحديث. الخطوات في `docs/ops/backup-restore.md` ← «الاسترجاع الحقيقي».
   - **أي شغل اتعمل بعد النسخة دي هيضيع.** عشان كده النسخة بتتاخد قبل التحديث بدقايق.
3. رجّع الكود زي الحالة 1.
4. اتأكد:

   ```bash
   node api/scripts/db-migrate.cjs plan
   ```

   على الكود القديم لازم يقول `pending: 0`.

## سجل الأخطاء

- **الملفات:** الأخطاء والتحذيرات بتتكتب في `api/logs/api-<التاريخ>.log` (ملف لكل يوم).
- **المدة:** اللي عدّى عليه 30 يوم بيتمسح لوحده.
- **التغيير:** في `api/.env`:
  - `LOG_DIR`: مكان تاني.
  - `LOG_RETENTION_DAYS`: عدد الأيام.
  - `LOG_DIR=off`: يقفل الملف.
- **لو حصلت مشكلة:** افتح ملف النهارده، وابعت آخر سطور `ERROR` للمبرمج.

## HTTPS (لازم لتثبيت التطبيق على الموبايل وإشعارات الجهاز)

- **ليه:** المتصفح مابيعرضش «تثبيت التطبيق» ولا إشعارات الجهاز إلا على عنوان آمن (HTTPS). السيرفر دلوقتي شغال HTTP على رقم IP، فالنظام شغال عادي من متصفح الموبايل بس من غير تثبيت. على `localhost` الاتنين بيشتغلوا من غير شهادة (للتجربة).
- **المطلوب مرة واحدة (من مسؤول السيرفر والشبكة):**
  1. **اسم للنظام** على الشبكة بيشاور على السيرفر (مثلًا `hr.<دومين الشركة>`). الشهادة بتتعمل لاسم، مش لرقم IP.
  2. **شهادة للاسم ده:** من شهادات الشركة الداخلية (والأجهزة والموبايلات لازم تكون واثقة فيها)، أو شهادة عامة لو الاسم على دومين عام.
  3. **proxy قدام الخدمتين** بيقدّم الشهادة (IIS أو nginx أو Caddy): `https://<الاسم>/` للواجهة (المنفذ 3000)، و`https://<الاسم>/api/` للـAPI (المنفذ 4000).
  4. **الإعدادات:** في `api/.env`: `FRONTEND_URL=https://<الاسم>` و`TRUST_PROXY=1`. وفي `.env.production.local` في جذر المشروع: `NEXT_PUBLIC_API_URL=https://<الاسم>/api`، وبعدها بناء الواجهة من جديد (القيمة بتتحط وقت البناء).
- **التأكد:** افتح النظام من كروم على موبايل أندرويد وادخل: في آخر القايمة الجانبية هيظهر «ثبّت التطبيق على الجهاز». على آيفون: من سفاري «مشاركة ← إضافة إلى الشاشة الرئيسية».
- **مفيش حاجة من ده في الكود:** الشهادة وإعداد الـproxy على السيرفر، ومفيش مفاتيح ولا كلمات سر بتتكتب في المشروع.
