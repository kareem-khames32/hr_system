# تجهيز عميل جديد وترقية النسخ

كل عميل **نسخة مستقلة**: قاعدة بيانات لوحدها + ملف بيئة لوحده + مجلد ملفات لوحده، بنفس الكود. مفيش بيانات عميل في قاعدة عميل تاني.

الأوامر كلها من مجلد `api` بتاع نسخة التجهيز (اللي ملف بيئتها فيه بيانات خادم SQL).

## 1. تجهيز القاعدة

```bash
node scripts/customer.cjs new --database hr_c_<اسم> --country SA --entity "اسم الكيان القانوني" --admin-email admin@customer.example --preset standard
```

- `--database`: لازم يبدأ بـ`hr_c_` وبحروف صغيرة وأرقام وشرطة سفلية، **وماتكونش موجودة**. قاعدة موجودة = الأمر بيرفض.
- `--country`: `EG` أو `SA` — دولة الكيان والفرع الرئيسي (وعملتهم).
- `--preset`: `basic` أو `standard` أو `full` (الباقة: أنهي موديولات مفتوحة). الافتراضي `standard`.
- `--branch`: اسم الفرع الرئيسي (الافتراضي «الفرع الرئيسي»).

الأمر بيعمل بالترتيب:

1. قاعدة جديدة فاضية.
2. شكل الجداول من كيانات الكود.
3. حساب مدير النظام **مقفول ومن غير كلمة مرور**.
4. كل ملفات الترحيل بالمُرحّل المجمّع (`db-migrate.cjs`) بوضع «قاعدة جديدة»: 13 ملف قديم بيتسجّلوا «مغطّاة بالأساس» من غير تنفيذ (شكلهم موجود من الخطوة 2)، والباقي بيتطبق.
5. بذرة العميل: الأدوار، أنواع الطلبات والإجازات، الإعدادات، الكيان، الفرع، الباقة. **من غير أي موظف أو حساب تجريبي.**
6. فحص: دفتر الترحيلات كامل والفرق عن الكيانات صفر.
7. نسخة احتياطية «نقطة الأساس» للقاعدة الجديدة (في `HR_CUSTOMERS_BACKUP_DIR`، الافتراضي `D:/projects/hr_system_backups/customers`).
8. سطر في سجل النسخ (`HR_CUSTOMERS_REGISTRY`، الافتراضي `D:/projects/hr_system_customers/registry.json`).

**لو أي خطوة فشلت، القاعدة الجديدة بتتشال** — مفيش نص قاعدة متساب. صلّح السبب وشغّل الأمر تاني.

## 2. مجلد النسخة وملف بيئتها

1. نسخة من الكود في مجلد العميل (نفس الإصدار).
2. `api/.env` للنسخة: نفس بيانات خادم SQL، و:
   - `DB_DATABASE=hr_c_<اسم>`
   - `HR_COMPANY_BACKUP=<مسار نسخة نقطة الأساس اللي الأمر طبعه>` — من غيرها ترقية النسخة بتقف.
   - `PORT` مختلف عن باقي النسخ، و`UPLOADS_ROOT` مجلد ملفات لوحده، و`JWT_SECRET` جديد.
   - بيانات بريد العميل (أو تتساب فاضية لحد ما تتظبط).
3. سجّل مجلد النسخة في سجل النسخ (خانة `apiRoot`) — أو شغّل `new` من الأول بـ`--instance-api-root <مسار api بتاع النسخة>`.

## 3. كلمة مرور المدير

من مجلد `api` بتاع **نسخة العميل**:

```bash
node scripts/set-password.cjs admin@customer.example
```

الكلمة بتتكتب مخفية ومابتتطبعش، والحساب بيتفعّل. المدير هيتطلب منه يغيّرها أول دخول.

## 4. بعد أول دخول

- **حزمة الدولة** (الإعدادات ← حزمة الدولة): صفوفها «محتاج تحقق» لحد ما تتراجع وتتعلّم «اتأكد» — وأي حساب قانوني مقفول لحد كده.
- سلاسل اعتماد أنواع الطلبات فاضية: حط المعتمدين.
- **استيراد البيانات من Excel** (الإعدادات ← استيراد بيانات التجهيز، لحساب «كل الفروع»): الهيكل الأول (فروع وأقسام)، وبعده الموظفين (براتبهم الأساسي). لكل نوع: نزّل القالب ← املاه ← ارفعه للمعاينة ← صلّح الأخطاء اللي بتظهر بالصف ← طبّق. إعادة رفع نفس الملف آمنة (الموجود بيتخطّى).
- الأرصدة الافتتاحية والسلف القائمة: **لسه بيتبنوا** (B6.1 ج).

## 5. ترقية كل النسخ

بعد تحديث الكود في مجلدات النسخ:

```bash
node scripts/customer.cjs upgrade-all --plan-only   # قراءة بس: إيه اللي ناقص في كل نسخة
node scripts/customer.cjs upgrade-all               # التطبيق
```

- لكل نسخة في السجل، المُرحّل بيشتغل **من مجلدها** بملف بيئتها وبحراسته كاملة: نسخة احتياطية لحظة التجميد، والـAPI بتاع النسخة لازم يكون واقف، وبروفة جوه معاملة قبل التطبيق.
- نسخة فشلت مابتوقّفش الباقي، وبتتكتب بسببها (والأمر بيخرج بكود خطأ).
- `node scripts/customer.cjs list` بيعرض النسخ المسجّلة.

## ملاحظات

- قاعدة الشركة الحالية (`hr_system`) **مش** في السجل وبتترقّى بطريقتها (`docs/ops/deploy.md`).
- الأمر مابياخدش ولا بيطبع أي كلمة مرور.
- كل النسخ على خادم SQL المضبوط في ملف بيئة التجهيز.
