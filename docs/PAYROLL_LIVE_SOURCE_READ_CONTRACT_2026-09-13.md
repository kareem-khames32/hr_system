# قراءة مصادر الرواتب الفعلية — العقد الأول، 13 سبتمبر 2026

هذا توثيق الإصدار الأول. أضافV2 سجل الأجر المؤرخ وقسم أدلة الجدول في [عقد السريان](PAYROLL_DATED_SOURCE_CONTRACT_2026-09-13.md)، وأكمل الإصدار الحالي`SRS_LIVE_SOURCE_READ_V3_20260913`التقويم المؤرخ وإثبات الحضور العادي في [عقد التقويم والحضور](PAYROLL_CALENDAR_ATTENDANCE_CONTRACT_2026-09-14.md). تبقى صلاحيات القراءة واتساقها وأعلام عدم التنفيذ كما هي. وصف عدم وجود تاريخ أجر أو تقويم أدناه يخص الإصدار الأول، ولا يلغي الإضافات اللاحقة.

## النطاق

يوفر `SRS_LIVE_SOURCE_READ_V1_20260913` قراءة خادمية لمصادر موظف وفترة ونسخة سياسة محددة. يشمل التغطية الوظيفية، قيم الأجر الحالية، أيام الحضور المخزنة، الإضافي المجمد عند الاعتماد، أرصدة الأقساط ومطالباتها، والمستحقات والمديونيات العامة. لا يستدعي حساب الحضور أو تجسيد الغياب ولا يصحح مصدرًا، ولا يحفظ مسيرًا أو يحجز موظفًا أو مبلغًا.

وجود بيانات مقروءة لا يثبت استحقاقًا تاريخيًا. تاريخ تغييرات ملف الموظف ليس تلقائيًا تاريخ سريان الأجر. كذلك صفوف الحضور المخزنة بالدقائق لا تصبح أدلة ثوانٍ خام أو جدول عمل تاريخيًا مكتملًا. لذلك هذه خطوة قراءة وجاهزية، وليست إغلاق PL-02/07 أو تفعيل المحرك على الرواتب الحالية.

## طلب القراءة

`POST /api/payroll/policies/:policyId/versions/:versionId/sources/read`

```json
{
  "expectedRevision": 3,
  "employeeId": 17,
  "periodStart": "2026-09-01",
  "periodEnd": "2026-09-30"
}
```

هذه المفاتيح الأربعة فقط. المعرّف والمراجعة عددان صحيحان موجبان ضمن SQL int. التواريخ فعلية، البداية لا تتجاوز النهاية، والفترة بحد أقصى32يومًا. الحد للتجميع القرائي وليس تغييرًا لمقام الشهر30. لا يقبل الطلب مبلغًا أو ترتيب تحصيل بديلًا أو مدخلات مالية يزعم العميل أنها موثقة أو `referenceRunId`.

الصلاحية `payroll.calculate`. يتأكد المنسق من ملكية قراءة السياسة ومن نطاق الموظف مستقلًا. سياسة عامة متاحة لمستخدم فرع لا تتيح له قراءة أجور موظف فرع آخر، وحتى الصلاحية `*` لا تلغي نطاق فرعه.

## اتساق القراءة

تُقرأ السياسة والموظف والمصادر على نفس EntityManager داخل معاملة `SERIALIZABLE`. قفل مشترك على `hr:payroll:policy:<id>` ينسق مع حفظ السياسة، وقفل مشترك على `hr:employee-finance:<id>` ينسق مع كاتبي المالية. SQL يحتفظ أيضًا بقراءات الصفوف والنطاقات الغائبة حتى انتهاء المعاملة. لا يستخدم المزود `READUNCOMMITTED` أو `NOLOCK`.

الأقفال مؤقتة للقراءة ولا تنشئ مطالبة أو حجز اعتماد. التعارض في مراجعة السياسة409، وعدم وجود السياسة/نسختها أو الموظف404، وتجاوز النطاق403. فشل الحصول على قفل يعيد409 `LIVE_SOURCE_BUSY`. أخطاء اتصال SQL غير المتوقعة لا تتحول إلى أرصدة صفرية.

## الاستجابة

- `readOnly:true`, `sourceValidation:"SERVER_READ_PARTIAL"`.
- `capturedAt`, `capturedBy`: وقت القراءة والقارئ من الخادم.
- `contentHash`: SHA-256 لمحتوى اللقطة بترتيب حتمي لمفاتيح الكائنات؛ قوائم الترتيب المالي تحتفظ بترتيبها. وقت الالتقاط لا يدخل بصمة المحتوى، فتتطابق قراءتان للمحتوى نفسه.
- `snapshot`: هوية مختصرة للموظف، الفترة، هوية السياسة ونسختها وتعريفها وإعداداتها وقرار التحصيل وإصداراتها، أقسام المصادر وأسباب عدم الجاهزية.
- `executionReady:false`, `approvalEligible:false`, `persisted:false` دائمًا لهذا العقد. اللقطة في الاستجابة وليست سجل PayrollRun/Item محفوظًا فيSQL.

يرفض مثبت المحتوى القيم غير القابلة للتمثيل دون فقد، مثل الأرقام غير الآمنة أو غير المنتهية والحقول `undefined`، بدل إسقاطها أو تحويلها إلىnull. هوية الموظف تُسقط صراحةً من كيانORM إلى قيمJSON محددة. يثبت الأجر وأموالSQL كنصوص عشرية قبل وصولها إلىNumber.

كل قسم يعيد `{state,data,issues,sourceRefs}`. `AVAILABLE` تعني أن المجموعة قابلة للقراءة وفق عقدها، ولا تعني اكتمال الحساب أو حقًا بالصرف. `MISSING` نقص، و`UNSUPPORTED` تفسير غير منفذ، و`INVALID` تعارض أو فساد. نقص أو فساد جزء مالي يجعل إجماليه غير المحسوم `null`؛ لا يظهر مجموع جزئي على أنه كامل.

الفترة الحالية هنا نافذة قراءة؛ `eligible` داخل المصدر مرشح بحسب المصدر والتاريخ والمطالبات فقط. لا يثبت سريان الأجر أو تغطية الموظف أو ملاءمة سياسة المسير. قواعد المقارنة والحساب الفعلي يجب أن تجمع هذه القرارات لاحقًا من نفس اللقطة.

تُقرأ أموالSQL بـCAST/CONVERT إلى نص. يُحتفظ بنصوص المطالبات ولقطات الاعتماد الخام عند فسادها بقدر الحدود. المصادر كبيرة الحجم لا تختصر إلى نتيجة مالية جاهزة: حد القراءة5000صف للمجموعة/القراءة المحددة في المزود، وحدود JSON والمحتوى تحمي الذاكرة وتنتج سببًا واضحًا عند تجاوزها.

## الواجهة

تحت `/payroll/policies` أضيف فحص المصادر إلى نسخة السياسة. يختار المستخدم موظفًا نشطًا من دليل النطاق وفترة صريحة؛ لا اختيار موظف تلقائي. API يسمح كذلك بالموظف غير النشط ضمن النطاق، بينما منتقي الواجهة الحالي للنشطين فقط.

تغيير الموظف أو الفترة يمحو النتيجة السابقة، وتغيير مراجعة السياسة يعيد تركيب الفحص. المسودة غير المحفوظة توقف القراءة حتى تُحفظ أو تُتجاهل. تعرض الشاشة الأجور الحالية بهذه الصفة، وحالات المصادر وأسباب النقص والاستبعاد، ولا تعرض أزرار اعتماد أو صرف لهذه القراءة.

## المرحلة التالية

يلزم استكمال مصادر سريان الأجر وجدول العمل التاريخي، ثم لقطةSQL مدققة وإسناد السياسة ودورة نشرها والمسير. إعادة الحساب من اللقطة نفسها افتراضيًا، وتحديثها بفروق وسبب صريح. حجز الموظف يظل عند الاعتماد. لا تغني اختبارات المصادر الصناعية عن ثلاث فترات تكافؤ كاملة متتالية وتشغيل ظل لشهرين قبل التبديل الإنتاجي.
