**الهدف:** نظام موارد بشرية متكامل احترافي (مصر + السعودية)، نبنيه Frontend-أولاً لكل مرحلة ثم Backend.

---

## 1. التقنية والمعمارية (Stack)

```
Monorepo
├── apps/web      → Next.js 14 (الفرونت الحالي)
├── apps/api      → NestJS (Node.js منظّم: modules/controllers/services)
├── packages/
│   ├── types     → أنواع مشتركة (مصدر واحد)
│   ├── config    → إعدادات الدول (EG/SA): عملة/ضرايب/تأمينات/قانون عمل
│   └── ui        → مكتبة مكوّنات موحّدة
DB: PostgreSQL + Prisma  |  Cache/Queues: Redis  |  Auth: JWT + RBAC
```

**محرّكات أساسية (Core Engines) تُبنى مرة وتُستخدم في كل مكان:**
1. **Requests & Approval Engine** — أي طلب + دورة اعتماد + استهداف + تنفيذ.
2. **Branch Scoping / RBAC** — عزل بيانات الفروع + صلاحيات.
3. **Notification Service** — إشعارات + قنوات + شعارات صفحة الموظف.
4. **Payroll Engine** — مسير + دورة اعتماد + حالة صرف + مراكز تكلفة.
5. **Attendance Engine** — بصمة + جدول مؤرّخ + حساب تأخير + أوفرتايم.

---

## 2. المبادئ الحاكمة (تنطبق على كل المراحل)

- **كل كيان مربوط بفرع (`branch_id`)** والبيانات معزولة: مدير الفرع يشوف فرعه فقط، الأدمن يشوف الكل.
- **الطلبات ودورات الاعتماد مقفولة على مستوى الفرع** — دورة اعتماد فرع المعادي ≠ فرع الرياض.
- **كل قسم/فريق/فرع له مدير مُسنَد** (يُستخدم في سلاسل الاعتماد "المدير المباشر").
- **كل طلب = نوع + حقول + دورة اعتماد + جمهور (من يراه)** — قابل للإنشاء من الإعدادات.
- **كل شيء ثنائي اللغة وقابل للتوطين** (الدولة إعداد).

## 3. المراحل (Frontend أولاً لكل مرحلة ثم Backend)

### 🟦 المرحلة 1 — الأساس: الداشبورد + الإعدادات الكاملة + ملف الشركة
**الهدف:** تأسيس الهيكل والمحرّكات قبل أي موديول.

**الإعدادات (تُراجَع وتُكمَّل):**
- ملف الشركة (متعدد الكيانات/الدول EG-SA).
- **الفروع** — كل فرع بمدير مُسنَد + مركز تكلفة.
- **الأقسام والفرق** — كل واحد بمدير مُسنَد (لسلاسل الاعتماد).
- المسميات + الدرجات (بنطاقات/steps) + **مراكز التكلفة**.
- **أيام العمل** (منفصلة عن الورديات) + العطل الرسمية.
- **أنواع الإجازات** + **إعداد الترحيل** (رصيد مُرحّل + صلاحية + حد أقصى).
- **بانِي دورات الاعتماد (Approval Builder)** — سلاسل متعددة المستويات + شروط + **لكل فرع**.
- **بانِي الطلبات (Request Builder)** — أنشئ أي طلب جديد + اربطه بدورة + حدّد جمهوره.
- **تسجيل أجهزة البصمة** (Device code ↔ الفرع) + إعداد سياسة الحضور.
- المستخدمين + **الأدوار (بنطاق فرع)** + أنواع/قوالب المستندات.
- **إعدادات الدولة** (ضرايب/تأمينات/قانون عمل EG-SA) + الإشعارات.
- **مراجعة الإعدادات** لإزالة التكرار وإضافة الناقص (خبرة HR).

**الداشبورد:**
- **لوحات حسب الدور** (أدمن / مدير فرع / موظف) بدل لوحة واحدة.
- **شعارات/مهام صفحة الموظف** (Action Items) + الإعلانات + التنبيهات.

### 🟩 المرحلة 2 — إدارة الموظفين
- CRUD حقيقي + ملف موظف كامل + **سجل تاريخي وظيفي (Job History)**.
- **العهد:** تعريف أنواع + تسليم للموظف (checkbox + تاريخ) **باعتماد اختياري** + إخلاء/إرجاع.
- العقود (تنبيهات/تجديد) + المستندات (صلاحية/تنبيه) + الهيكل + المؤرشفين.
- **Onboarding Checklist** للموظف الجديد.
- **الخدمة الذاتية:** "طلباتي" + "بياناتي" + **طلب تغيير بيانات** باعتماد.

### 🟨 المرحلة 3 — الحضور والانصراف
- **ربط البصمة بالكود** = مصدر الحضور (Device → سجل).
- **جدول أسبوعي مؤرّخ** + **محرّك حساب التأخير** حسب وردية اليوم.
- الأذونات (أنواع + خصم تجاوز المدة) + التقرير الشهري اليومي.
- **الأوفرتايم:** طلب موظف **أو توجيه تلقائي للمدير المباشر** عند تجاوز العتبة → اعتماد → **يدخل مسير الرواتب كإضافي**. (مين يعتمد = إعداد).
- **طلب بصمة عن بُعد** (للعمل عن بُعد) باعتماد مُحدَّد.

### 🟧 المرحلة 4 — الإجازات
- طلب إجازة يمشي في **دورة اعتماد الفرع** فعلياً.
- **الأرصدة:** رصيد افتتاحي/مُرحّل بصلاحية + تراكم تلقائي + ترحيل سنوي.
- تقويم الإجازات + الرسمية + الأنواع.

### 🟥 المرحلة 5 — مسير الرواتب + التقارير
- **إعداد فترة المسير** (مثل 23→22) + **مسير مستقل لكل فرع**.
- **دورة اعتماد كاملة** (محاسب → HR → مالي → **الرئيس التنفيذي** → جهة الصرف المحدَّدة).
- **حالة صرف جنب كل موظف** (كاش/فيزا/تحويل) لسحب تقارير المصروف.
- **مراكز التكلفة** — تحميل الرواتب على القسم/المركز + اعتماده.
- إلغاء خصم قبل القفل + توليد ملف بنك/WPS + توزيع قسائم.
- **تدفق الاستقالة والتصفية:** استقالة (مكان تقديم خاص) → اعتماد → فترة إشعار → تصفية **بدورة اعتماد تنتهي بإشعار الموظف** → قفل عقد → أرشفة → شهادة.
- التقارير المالية.

**(لاحقاً):** الأداء · التدريب · التوظيف · المنصة (BI/موبايل/تكاملات حكومية).

---

## 4. طريقة التنفيذ لكل مرحلة

لكل مرحلة نمشي بالترتيب ده:
1. **Front:** الشاشات + التدفقات (بحالة/بيانات وهمية موحّدة عبر طبقة data واحدة).
2. **Back:** جداول Prisma + API (NestJS) + ربط الفرونت بالـ API.
3. **Verify:** تشغيل + مراجعة + إغلاق المرحلة.

## 5. نبدأ الآن بـ: المرحلة 1 (الفرونت)

أول خطوات فعلية:
1. **هيكلة المشروع** (types + config الدول + مكتبة مكوّنات مشتركة).
2. **الإعدادات:** إضافة مدير لكل فرع/قسم/فريق + مراكز التكلفة + إعداد ترحيل الإجازات + تسجيل أجهزة البصمة.
3. **بانِي الطلبات + بانِي دورات الاعتماد (لكل فرع)** — الشاشات.
4. **لوحات حسب الدور + شعارات صفحة الموظف**.
