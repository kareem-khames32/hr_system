# مراجعة إصدار الخطابات وتزامن القرارات — 11 سبتمبر 2026

نطاق المراجعة: خدمات وقوالب الخطابات ومسار الاعتماد النهائي، تنزيل الملف وصلاحياته، `PdfPreview`، `MyApprovalDecisions`، وملخص `myDecisions`. لم تشمل تدقيقًا شاملًا لكل النظام.

**عيب مؤكد قبل الإصلاح:** كان فعل الاعتماد يقرأ الطلب قبل قفل المعاملة، بينما الرفض والإرجاع يكتبان خارجها. عند تداخل قرارين على الطلب نفسه أمكن أن يرجع الاعتماد `COMPLETED` بعد إصدار الخطاب، ثم يكتب الرفض القديم `REJECTED` فوقه. تجربة HTTP/SQL مع بوابتين محددتين أثبتت النتيجة: نجح القراران، وصارت الحالة النهائية مرفوضة مع وجود خطاب مولد وسجلي اعتماد ورفض.

الإصلاح لدى مسار تنفيذ الطلبات: قفل قراءة الطلب وقراره وسجل التدقيق وإصدار الوجهة داخل معاملة واحدة؛ القرارات اللاحقة تقرأ الحالة الملتزمة وترفض انتقالًا لم يعد مسموحًا.

الاختبار الدائم `api/test/request-decision-race.integration.cjs` يغطي الاعتماد مقابل الرفض والإرجاع والإلغاء بالترتيبين. يوقف مُولد PDF بعد امتلاك القفل، أو يوقف القرار الأول بعد قراءة الطلب، ويراقب انتظار قفل SQL الفعلي قبل تحرير البوابة. بذلك لا يعتمد الإثبات على ترتيب عشوائي لـ`Promise.all`. عند نجاح الاعتماد يفترض خطابًا واحدًا وسجل اعتماد واحدًا؛ وعند نجاح القرار المقابل أولًا يفترض عدم إصدار خطاب أو ملف. مولد المحتوى نفسه معزول عند حد الاختبار؛ صحة PDF العربي الفعلية يغطيها اختبار الخطابات في `recovery.integration.cjs`.

لم تُثبت المراجعة عيبًا حرجًا آخر في محرر القالب أو عارض PDF أو سجل القرارات: المحتوى يُهرب قبل عرضه في مولد PDF، والتنزيل يخضع لملكية الموظف أو صلاحية المستندات في النطاق، ومعاينة القالب تستعمل أمثلة موضحة. يحتفظ الإصدار بالنص المنشور المحفوظ، وملخص القرارات يعيد قرارات الحساب نفسه دون حمولة الطلب أو بيانات مقدمه.

النتيجة بعد الإصلاح: `node --test api/test/request-decision-race.integration.cjs` نجح **8/8**؛ ست حالات تزامن محكومة بالبوابات وانتظار قفل SQL الفعلي، وحالتان إضافيتان تثبتان رفض سبب الرفض/الإرجاع الغائب أو المكون من مسافات دون سجل تدقيق أو تغيير حالة، وحفظ السبب الصحيح بعد إزالة المسافات الطرفية. بذلك أُغلق العيب المثبت ضمن نطاق هذه المراجعة.

الاختبار يستخدم بيئة اختبار منفصلة؛ لا يحتوي التقرير على بيانات اتصال أو أسرار. الفحص لا يدعي تغطية كل مسارات الطلبات؛ اختبار التقديم وإعادة التقديم المتزامنين وبقية اختبارات التنفيذ لدى الوكيل المسؤول عن الإصلاح.
