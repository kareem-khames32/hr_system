# HR System – Technical Review & Multi-Country Vision
# المراجعة الفنية ورؤية تعدّد الدول (مصر + السعودية)

**التاريخ:** 2026-07-07
**الغرض:** مراجعة فنية/معمارية للكود نفسه (مش المحتوى الوظيفي)، وبناء رؤية معمارية كاملة، مع جعل النظام **متعدد الدول** يناسب **مصر والسعودية** كإعداد قابل للتغيير.

---

## 1. لقطة فنية للمشروع (بالأرقام)

| المؤشر | القيمة | الدلالة |
|--------|:---:|---------|
| صفحات (`page.tsx`) | **71** | تغطية شاشات واسعة جداً |
| مكوّنات مشتركة (`components`) | **10** فقط | شبه معدوم — لا مكتبة مكوّنات |
| إجمالي أسطر الكود | **~39,000** | ضخم نسبةً لـ10 مكوّنات = تكرار هائل |
| تعريفات `interface` مضمّنة | **65** في 58 ملف | الأنواع مكرّرة داخل كل صفحة، لا types مشتركة |
| مصفوفات بيانات وهمية مضمّنة | **90** | البيانات hardcoded داخل كل صفحة |
| استدعاءات `useState` | **413** | كل الحالة محلية ومؤقتة تضيع عند التحديث |
| أزرار وهمية (`alert`/`console.log`) | **25** | وظائف غير منفّذة |
| مجلدات البنية التحتية (lib/hooks/api/store/types/utils/services/config/i18n) | **صفر** | لا توجد أي طبقة معمارية |

## 2. الموجود فنياً (نقاط القوة)

- **Next.js 14 (App Router) + TypeScript + TailwindCSS** — أساس تقني حديث وسليم.
- **`tsconfig` صارم** (`strict: true`) + **مسار مختصر** (`@/*`) مُهيّأ.
- **تصميم بصري متسق وعالي الجودة** (RTL، نظام ألوان، بطاقات) عبر كل الشاشات.
- **تغطية شاشات واسعة** (71 صفحة تغطّي معظم موديولات HR).
- **توثيق ممتاز** (`DATABASE_SCHEMA`, `ERD`, `SYSTEM_DESIGN`, `WORKFLOWS`) — مخطط بيانات جاهز يسبق الكود.

---

## 3. الناقص فنياً (الفجوات المعمارية الحرجة)

### 3.1 لا توجد طبقة خلفية (Backend) إطلاقاً
- **لا API** (لا `src/app/api`, لا `route.ts`) — صفر endpoints.
- **لا قاعدة بيانات ولا ORM** (لا Prisma/Drizzle) — المخطط SQL موثّق لكن غير منفّذ.
- **لا مصادقة حقيقية:** صفحة تسجيل الدخول تعمل `window.location.href = '/'` **بغضّ النظر عن المدخلات** — لا تحقق، لا JWT، لا حماية مسارات (route guards).

### 3.2 لا توجد طبقة بيانات ولا إدارة حالة
- **90 مصفوفة بيانات وهمية مبعثرة** داخل الصفحات — لا مصدر حقيقة واحد (Single Source of Truth).
- **413 `useState` محلية** — كل تعديل يضيع عند التحديث؛ لا مزامنة بين الشاشات.
- **لا مكتبة جلب بيانات** (React Query/SWR) ولا **إدارة حالة** (Zustand/Redux) ولا **تحقق** (Zod) ولا **نماذج** (React Hook Form).

### 3.3 تكرار هائل وغياب إعادة الاستخدام
- **65 تعريف `interface` مكرّر** — مثال: `interface Notification` مُعرّف مرتين منفصلتين (في الصفحة وفي الهيدر) وغير متزامنين.
- **10 مكوّنات فقط لـ71 صفحة** — لا مكتبة مكوّنات (Button/Table/Modal/Form/Card موحّدة)؛ كل صفحة تعيد كتابة كل شيء.
- **لا مجلد `types` مشترك، ولا `lib`/`utils`** لدوال الحساب (تواريخ، عملة، رواتب) — منطق الحساب مكرّر ومتضارب (مثلاً حساب مكافأة نهاية الخدمة مختلف بين شاشتين).

### 3.4 لا جودة ولا أتمتة
- **لا اختبارات** (لا Jest/Vitest/Playwright/Cypress).
- **لا ESLint/Prettier مُهيّأ، لا Husky، لا CI/CD**.
- **لا معالجة أخطاء موحّدة** (error boundaries/toasts) — الأزرار تستخدم `alert()`.

### 3.5 غير جاهز للتدويل ولا للجوال
- **لا بنية i18n** (لا `next-intl`/`i18next`, لا `locales`) — **كل النصوص عربية مثبّتة داخل JSX**؛ الإنجليزية غير منفّذة.
- **غير متجاوب (Not Responsive):** تخطيطات ثابتة (`grid-cols-4`, sidebar بعرض ثابت `fixed`) — لن يعمل على الجوال.

### 3.6 التوطين مدموج في الكود (المشكلة المحورية لطلبك)
- **157 ذكر لـ SAR/ريال** + **72 ذكر لـ GOSI/تأمينات** مبعثرة داخل الشاشات، مقابل **2 فقط لـ EGP** و**4 للهجري**.
- يعني النظام **مربوط بالسعودية داخل الكود نفسه** (عملة، تأمينات، قانون) — **لا يمكن تحويله لمصر بإعداد**؛ يحتاج تعديل عشرات الملفات يدوياً. **هذه أكبر عقبة أمام تعدّد الدول.**

## 4. الرؤية المعمارية المستهدفة (Target Architecture)

بناء النظام على طبقات واضحة بدل كتلة الواجهة الحالية:

```
┌─────────────────────────────────────────────────────────────┐
│  UI Layer: مكتبة مكوّنات موحّدة (Button/Table/Modal/Form) +   │
│            صفحات نحيفة تستهلك البيانات فقط                    │
├─────────────────────────────────────────────────────────────┤
│  State/Data: React Query (جلب/كاش) + Zustand (حالة) +        │
│              React Hook Form + Zod (تحقق)                     │
├─────────────────────────────────────────────────────────────┤
│  Shared: types/ (أنواع موحّدة) + lib/ (تواريخ/عملة/حسابات) + │
│          i18n/ (ar/en) + config/ (إعدادات الدولة)            │
├─────────────────────────────────────────────────────────────┤
│  API Layer: REST/tRPC endpoints + مصادقة JWT + route guards  │
├─────────────────────────────────────────────────────────────┤
│  Services / Rule Engines: محرّك رواتب + محرّك إجازات +        │
│     محرّك اعتمادات + محرّك التوطين (Localization Engine)      │
├─────────────────────────────────────────────────────────────┤
│  Data: PostgreSQL + ORM (Prisma) + طبقة وصول + RLS للفروع    │
└─────────────────────────────────────────────────────────────┘
Cross-cutting: Auth · Audit Log · Notifications · Tests · CI/CD
```

**نقلات فنية أساسية:**
1. استخراج **مكتبة مكوّنات** موحّدة + مجلد **`types`** مشترك (إزالة الـ65 تكرار).
2. استخراج **`lib/`** لدوال الحساب (تاريخ/عملة/رواتب/نهاية خدمة) كمصدر واحد.
3. طبقة **API + قاعدة بيانات + مصادقة** حقيقية بدل الـ hardcoded.
4. **React Query + Zustand** بدل الـ413 useState.
5. بنية **i18n** + جعل التصميم **متجاوباً**.
6. **اختبارات + ESLint/Prettier + CI**.

## 5. محرّك التوطين متعدد الدول (Localization Engine) — مصر + السعودية

> الفكرة: **الدولة تصبح إعداداً (Country Profile)** يقود كل القواعد المتغيّرة، بدل دمجها في الكود. تضيف دولة = تضيف ملف إعداد، بدون لمس الشاشات.

### نموذج الإعداد المقترح
```
country_profiles → code (SA|EG), currency, calendar_primary,
   weekend_days, id_types[], tax_engine, social_insurance_engine,
   labor_law_ruleset, contract_templates[], gov_integrations[]
```

### ما الذي يتغيّر بين مصر والسعودية (جدول القرار)

| البُعد | 🇸🇦 السعودية | 🇪🇬 مصر |
|--------|-------------|---------|
| العملة | ريال (SAR) | جنيه (EGP) |
| التقويم | هجري + ميلادي | ميلادي (هجري اختياري) |
| **ضريبة الدخل** | **لا يوجد** | **ضريبة كسب عمل تصاعدية (شرائح)** |
| التأمينات | **GOSI** (حد 45,000، جدول 2025) | **التأمينات الاجتماعية المصرية** (شرائح/نِسب مختلفة) |
| قانون العمل | نظام العمل السعودي | **قانون العمل المصري (12/2003 والجديد 14/2025)** |
| الإجازة السنوية | 21 يوم (30 بعد 5 سنوات) | 21 يوم (30 بعد 10 سنوات أو سن 50) |
| مكافأة نهاية الخدمة | م.84/85 (نصف شهر ثم شهر) | **صيغة مصرية مختلفة** + معاش |
| فترة التجربة | حتى 90 يوم | **حتى 3 شهور** |
| الأعياد الرسمية | تقويم سعودي | **تقويم مصري** |
| التوطين | **نطاقات/سعودة** | لا يوجد (كوتة ذوي الهمم 5%) |
| التكاملات الحكومية | WPS/قوى/مدد/GOSI/أبشر/نفاذ | **التأمينات المصرية/مصلحة الضرائب** |
| نوع الهوية | هوية وطنية / **إقامة** للوافد | **الرقم القومي** |
| عطلة نهاية الأسبوع | جمعة + سبت | جمعة + سبت (أو جمعة) |

### ما الذي يجب أن يصبح "قابلاً للإعداد" (Configurable) بدل مثبّت
1. **محرّك ضرائب (Tax Engine)** بشرائح لكل دولة (مصر: شرائح؛ السعودية: صفر).
2. **محرّك تأمينات (Social Insurance Engine)** بقواعد لكل دولة (GOSI مقابل التأمينات المصرية).
3. **مجموعة قواعد قانون العمل (Labor Law Ruleset):** الإجازات، نهاية الخدمة، فترة الإشعار، معاملات الأوفرتايم، فترة التجربة — كلها قيم في إعداد الدولة.
4. **العملة والتقويم والأعياد** من إعداد الدولة (إزالة الـ157 SAR المبعثرة).
5. **قوالب العقود والمستندات** لكل دولة (عربي بصيغة كل جهة).
6. **أنواع الهوية والتكاملات الحكومية** حسب الدولة.

> يُفضّل أن يكون الإعداد على مستوى **الشركة/الفرع** (multi-country tenancy) — بحيث تدير كيانات في مصر والسعودية معاً في نفس النظام، كل فرع بقواعده.

## 6. الخلاصة: الموجود / الناقص (فنياً — نظرة عامة)

### ✅ الموجود
- أساس تقني حديث (Next 14 + TS صارم + Tailwind)، تصميم بصري ممتاز، 71 شاشة، وتوثيق بيانات قوي.

### ❌ الناقص (فنياً)
1. **لا Backend/DB/API/مصادقة** — النظام واجهة فقط.
2. **لا طبقة بيانات ولا إدارة حالة** (90 مصفوفة وهمية + 413 useState).
3. **لا مكتبة مكوّنات ولا types مشتركة** (تكرار ضخم، 65 interface مكرّر، 10 مكوّنات فقط).
4. **لا `lib` لدوال الحساب** (منطق مكرّر ومتضارب).
5. **لا i18n ولا تصميم متجاوب ولا اختبارات ولا CI**.
6. **التوطين مدموج في الكود** → **غير قابل للتحويل لمصر بإعداد** (أكبر عقبة لطلبك).

### 🎯 المطلوب لتحقيق الرؤية
طبقات معمارية واضحة + **محرّك توطين (Country Profile)** يجعل مصر/السعودية إعداداً + مكتبة مكوّنات + طبقة بيانات/API/مصادقة حقيقية + i18n + تجاوب + اختبارات.

## 7. ترتيب العمل الفني المقترح

**دفعة فنية 1 — الأساس المشترك:** استخراج `types/` + `lib/` (تاريخ/عملة/حسابات) + مكتبة مكوّنات + **`config/country/` (SA + EG)**.
**دفعة 2 — طبقة البيانات:** DB (Prisma/Postgres) + API + React Query + إزالة الـ hardcoded تدريجياً.
**دفعة 3 — المصادقة والصلاحيات:** Auth حقيقي + route guards + Multi-Branch RBAC + Audit.
**دفعة 4 — التدويل والتجاوب:** بنية i18n (ar/en) + جعل الشاشات متجاوبة.
**دفعة 5 — محرّكات القواعد:** محرّك رواتب/تأمينات/ضرائب/إجازات مبني على Country Profile.
**دفعة 6 — الجودة:** اختبارات + ESLint/Prettier + CI/CD.
